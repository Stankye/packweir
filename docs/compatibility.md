# Compatibility and roadmap

All native adapters are experimental. The [container client matrix](containers.md) qualifies selected authenticated install flows with six real clients against local fixtures using filesystem and S3-compatible storage. Full protocol conformance and broader version coverage remain open. The implementation preserves package bytes while rewriting discovery/download locations. It does not claim Nexus or Artifactory feature parity.

| Ecosystem | Implemented routing | Important limitations |
|---|---|---|
| npm | Packuments, tarball links with SHA-512/SHA-1 binding, JSON security-resource forwarding | No publish, vulnerability-audit POST API, namespace reservation, or automatic provenance retrieval/verification. Download URLs outside configured origins are rejected. |
| PyPI | HTML and JSON simple indexes, distribution/hash links, requires-python/yanked metadata | PEP 658 sidecar advertisement is disabled so clients download the gated distribution. JSON hashes use SHA-256 when supplied. Native attestation retrieval/verification is not implemented. Bzip2, XZ, Zstandard, RAR, and 7z archives are rejected until bounded inspection is implemented. |
| Cargo | Sparse index, generated authenticated config, checksum-bound crate download route; `cargo:token` exercised in the client matrix | No Git index, publishing, owner/yank API, or broader credential-provider/version conformance validation. |
| Maven / Gradle | Artifact paths, POMs, snapshots, metadata, checksum/signature sidecars | Proxy POMs and artifacts are gated individually. Hosted immutable releases use native Gradle publication, sealed manifests, and explicit evidence-bound promotion; see [hosted releases](hosted.md). Native signatures and snapshot publishing remain unfinished. Configure `cache_max_age_seconds` for mutable paths; conditional revalidation and Maven-specific snapshot resolution remain unfinished. |
| NuGet | V3 proxy discovery rewriting; hosted staged native push, immutable normalized identities, flat-container versions/packages/nuspec/SHA-512, scoped authentication and source reservations | See [NuGet hosting](nuget.md). No hosted search/registration, unlist/delete, symbol publishing, trusted-signer server policy, or built-in package signature verifier. Original signed package bytes remain unchanged. |

Single byte ranges are served only after complete artifact approval. Multiple ranges and conditional requests are not implemented. The gateway fetches complete bounded responses and does not promise streaming large-artifact performance. Client-provided credentials are never forwarded upstream. Configured upstream bearer secrets are origin-scoped; other upstream authentication schemes need adapters/configuration support.

ZIP inspection and OSV database validation require consistent local and central headers, unique central-directory names, and nonoverlapping entries. Ambiguous archives are rejected even when a permissive client could read them. The ZIP parser is exactly pinned to [9.4.1](https://github.com/zip-rs/zip2/releases/tag/v9.4.1); strict consistency validation also rejects unlisted local file headers in gaps. Hosted NuGet inspection additionally checks bounded central-directory counts before indexing, all entry CRCs, descriptor fields, extraction-path aliases, and the root nuspec. Version 0.6.0 changes the engine version included in evidence fingerprints, so older approvals require fresh analysis. Upgrade gateways and workers together.

Cache hits reuse retained original bytes and reevaluate current policy. Optional per-repository `cache_max_age_seconds` performs full upstream revalidation when due; unchanged bytes preserve evidence expiry, changed or reverted bytes require fresh approval, and failures cannot release stale bytes. Without this setting, retained URLs keep the immutable-cache behavior. See [operations](operations.md). With `retain=false`, approved bytes are deleted after delivery if no retaining repository or active analysis references them. Denied, abandoned, failed-analysis, and superseded blobs require future garbage collection; there is no automatic retention/TTL collector yet. Job fetch/scan deduplication is database-backed for scans and process-local for fetches. Requests can duplicate upstream work across multiple gateway replicas.

Current jobs are retried up to three times per queued run with lease recovery; exhausted expired leases become failed jobs. Evidence-context changes and manual rescans invalidate existing findings, and lease ownership/context checks prevent old workers from committing stale results. Adapters have wall-clock/output limits; full worker resource scheduling and isolation remain external responsibilities.

[Package identities and scoped policies](policies.md) provide registry-path observations, additive repository and npm-namespace/Maven-group/exact-package requirements, independent delivery fingerprints over shared blobs, and CLI/API explanations. These do not establish publisher ownership, source trust, general private/public routing precedence, automatic attestation discovery, or exception workflows. Maven source reservations and hosted release promotion are documented separately in [hosted releases](hosted.md).

Sigstore v0.3 blob signatures, selected source-bound SLSA artifact verification, offline OSV mapped/observed-package checks, and Hipcheck source policies are available through built-in drivers. Automatic source/provenance discovery, additional builder/statement support, and package-manager-native signatures remain separate work. See the [integration catalog](integrations.md) and [native driver limits](native-drivers.md) for configuration and tool-specific status.

## Milestones

Implemented follow-up capabilities include [file-license observations](licenses.md), optional observed-coordinate OSV scans, mutable-cache revalidation, and authenticated [operational snapshots/metrics](operations.md). Complete license compliance, process/VM isolation, safe garbage collection, broader hosted protocols, remote federation, and OCI transport remain unfinished. Cross-repository Maven/NuGet promotion with fresh destination checks and captured lineage is implemented; see [promotion](promotion.md). Staged immutable hosting, scoped service credentials, and source reservations are implemented for [Maven](hosted.md) and [NuGet](nuget.md).

1. **Finish the initial evidence proxy:** Windows compilation, PostgreSQL tests, selected native-client flows, filesystem/S3-compatible container qualification, file-license observations, operational metrics, and mutable-artifact revalidation are implemented. Broaden client/version and storage-provider coverage; implement additional trusted scanner adapters, native provenance retrieval/verifiers, complete SBOM validation, license review workflows, safe garbage collection, and namespace routing controls.
2. **Deep analysis and advanced clients:** [conditional agent scheduling](agent-escalation.md) and bounded [Microsoft rule observations](ossgadget.md) are implemented. Add provider-specific agents, the remaining OSSGadget tools, selective Ghidra/deobfuscation, Assemblyline v4 submission/result integration, OpenSSF Package Analysis, audit APIs, license obligation reports, a supported client/version matrix, and external OCI artifact/report storage through ORAS. OpenDAL remains the blob-storage abstraction; OCI artifact exchange is a separate transport capability.
3. **Hosted repositories:** immutable Maven/NuGet staging/publication, source ownership, scoped read/write/promote permissions, quarantine, digest-bound manifests, cross-repository staging with fresh destination checks, lineage exports, and revocation are implemented. Extend native publishing to npm/PyPI/Cargo, add repository groups, general RBAC, remote repository federation, signing workflows, scoped review/exception workflows, and an administrative UI.
4. **OCI distribution:** add hosted/proxied OCI manifests, blobs, tags, referrers, authentication, and ORAS conformance tests.
5. **Specialized sandboxing:** integrate dedicated DRAKVUF-class workers and optional operator-provided THOR. Assemblyline v4 (ASv4) is the external analysis platform in milestone 2; it is distinct from a dedicated VM execution backend. Available analysis depends on the services deployed in the operator's Assemblyline instance.

Provenance claims, SBOM completeness, vulnerability findings, license obligations, source posture, and malicious behavior are separate evidence categories. No overall score should silently substitute for an explicit required policy check. The [product scope](product-scope.md) defines the proposed assurance boundaries and validation gates; the remaining milestone items are planned work. Implemented slices are identified above; no milestone constitutes a compliance claim.
